## 2024-06-25 - Avoid spreading strings and `.slice()` inside nested loops for string comparisons
**Learning:** In string comparison logic like finding common prefixes or suffixes, spreading strings into character arrays `[...str]` and performing `.slice(0, -1)` allocations inside `while` and `for` loops puts massive pressure on the garbage collector. Specifically in `packages/format/src/pipeline/column-template.ts`, the `longestCommonSuffix` implementation would map strings to character arrays, spread them, reverse them, and `.join()`, resulting in terrible performance overhead (over ~95% slower). Additionally, index-based looping correctly matches and processes UTF-16 surrogate pairs sequentially without mutating them.
**Action:** Always prefer native index-based character matching using loops `for (let i = 0; i < str.length; i++) { const char = str[i]; }` or similar index iteration logic, which performs in-place evaluation with O(1) space complexity. Avoid high-allocation string methods (`.slice()`, `.split()`) inside performance-critical outer loop boundaries.
